# axiom-runtime v0.2.0

Исполнение `AXIOM-PROGRAM/2` только через proof gate. Символический receipt для неограниченной области допускает вход `i64` без дополнительного
ограничения диапазоном; переполнение при исполнении отклоняется; доказательство, ограниченное диапазоном, остаётся ограниченным этим диапазоном. Любое
изменение артефакта аннулирует авторизацию благодаря SHA-256-привязке.

## Связанные исследования

Этот компонент входит в исследовательский проект [Axiom](https://github.com/localzet/axiom-stack). Все компоненты собраны по теме [localzet-axiom](https://github.com/topics/localzet-axiom). Основной язык документации — русский. Исследовательские результаты и ограничения не означают готовность к промышленному применению.

## Границы доверия и числовой модели

Receipt принимается из доверенного локального proof-producing pipeline: этот прототип проверяет привязку хешей и поля результата, но не аутентифицирует автора receipt и не перепроверяет математическое доказательство. Самодельный `VALID` receipt с пересчитанными хешами нельзя принимать от недоверенного участника. Для такого режима необходимы проверяемый proof backend или отдельная аутентифицированная verifier authority.

Lean/symbolic модель работает с математическими целыми, VM — с `i64`. NEG/ADD/SUB возвращают ошибку при переполнении; например, `abs(i64::MIN)` не представим в `i64` и не выдаётся как ошибочный отрицательный результат. Формальное соответствие VM математической модели ещё не доказано. Некорректные/повторяющиеся поля артефакта и недостающая область отклоняются.
